LACP, Trunk & RAID

Intermediate

Overview

This lesson covers three infrastructure capabilities available in OPCP and how they are configured using the platform's tools. In OPCP, these features are managed through OpenStack APIs and the opcp-cli tool — network switches are automatically configured based on your OpenStack settings.

Key principle: Network configuration in OPCP is driven by Horizon/API (Neutron). Physical switches are automatically configured from the information set in OpenStack — no manual switch access is needed.

LACP — Link Aggregation

What It Is

LACP (Link Aggregation Control Protocol) combines multiple network interfaces into a single logical bond, providing increased bandwidth and failover protection.

In one sentence: LACP combines multiple network connections into one faster, more reliable link — like adding extra lanes to a motorway.

How It Works in OPCP

LACP configuration in OPCP is managed via the opcp-cli tool or the OpenStack API:

  • Bond interfaces are configured at the node level during provisioning
  • The switch-side LACP configuration is applied automatically by the platform
  • No manual switch configuration is required
# LACP bond configuration is managed via opcp-cli
# The platform handles both host-side and switch-side configuration

Benefits

  • Increased bandwidth — Multiple links aggregated into a single logical connection
  • High availability — If one link fails, traffic continues on remaining links
  • No single point of failure — Redundancy at the network interface level
  • Automatic switch configuration — The platform configures switches to match

Trunk — Network Traffic Organisation

What It Is

A network trunk allows a single physical port to carry traffic for multiple networks (VLANs) simultaneously. In OPCP, trunking is managed through OpenStack Neutron.

In one sentence: Trunking organises network traffic into separate channels on one connection — like sorting mail into different mailboxes at the same address.

How It Works in OPCP

Trunk port configuration is handled via the Neutron API or Horizon dashboard:

  • Create trunk ports in Neutron to carry multiple VLANs on a single physical port
  • Add sub-ports to the trunk for each network/VLAN
  • Physical switch trunk configuration is applied automatically from the OpenStack settings
# Create a trunk port via OpenStack CLI
openstack network trunk create --parent-port $PARENT_PORT my-trunk

# Add a sub-port to the trunk
openstack network trunk set --subport port=$SUB_PORT,segmentation-type=vlan,segmentation-id=100 my-trunk

# List trunks
openstack network trunk list

Benefits

  • Network isolation — Different workloads or tenants on separate VLANs
  • Efficient use of ports — Multiple networks over a single physical connection
  • Security boundaries — Sensitive traffic isolated from general traffic
  • Automatic switch config — Neutron drives the physical switch trunk setup

Software RAID — Data Protection

What It Is

Software RAID (Redundant Array of Independent Disks) distributes data across multiple drives for protection against disk failures. In OPCP, software RAID is configured during node provisioning.

In one sentence: RAID protects data by storing copies across multiple drives — like keeping backup copies of important documents in separate filing cabinets.

How It Works in OPCP

Software RAID configuration is part of the instance deployment process:

  • RAID level is selected during node provisioning (via deploy templates or instance metadata)
  • Configuration is applied by Ironic during the deployment phase
  • Common configurations: RAID 1 (mirroring), RAID 5 (striping with parity), RAID 10 (mirrored stripes)
# RAID configuration is defined in the node's deploy template
# or via Ironic's RAID interface during provisioning
openstack baremetal node set $NODE_ID \
  --target-raid-config '{"logical_disks": [{"size_gb": "MAX", "raid_level": "1", "is_root_volume": true}]}'

# Trigger RAID configuration (in clean step)
openstack baremetal node clean $NODE_ID \
  --clean-steps '[{"interface": "raid", "step": "create_configuration"}]'

Benefits

  • Data safety — Data survives individual disk failures
  • Continuous operation — System keeps running even when a drive fails
  • Configurable at provisioning — Choose the right RAID level for each workload
  • Automatic rebuild — When a failed drive is replaced, data is reconstructed automatically

Quick Comparison

Feature Configuration Method Tool Key Benefit
LACP Bond configuration at node level opcp-cli / API Bandwidth + redundancy
Trunk Trunk ports with sub-ports per VLAN Neutron API / Horizon Network isolation + efficiency
Software RAID Defined during node provisioning Ironic (deploy templates) Data protection + availability

Key Takeaways

  • LACP is configured via opcp-cli or API — switches are auto-configured by the platform
  • Trunk ports are managed through OpenStack Neutron — no manual switch access needed
  • Software RAID is configured during node provisioning via Ironic
  • All network configuration is driven by OpenStack — physical switches follow automatically
  • The platform eliminates the need for manual switch configuration
