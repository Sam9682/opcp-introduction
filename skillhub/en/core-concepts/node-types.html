Understanding Nodes in OPCP

In OPCP, a node represents a physical server (bare metal) managed via OpenStack Ironic. Unlike virtual machines in traditional cloud environments, OPCP nodes are dedicated physical hardware — the full power of the server is available to your workloads without virtualisation overhead.

Different hardware configurations (or "profiles") are available in the rack. When a server boots, the OPCP control plane automatically detects its hardware properties — CPU model, RAM capacity, storage drives, network interfaces — and registers these as traits in the Ironic inventory.

Key concept: A node is the physical server configuration. An instance is the OS running on that node. They are managed separately in OPCP.

Automatic Hardware Discovery

When a physical server boots in the OPCP rack, the platform automatically discovers:

  • CPU — Model, number of cores, architecture
  • RAM — Total capacity, type (DDR4/DDR5), speed
  • Storage — Number and type of drives (SSD, NVMe, HDD), capacities
  • Network — Interface count, speed (10G, 25G, 100G), capabilities
  • GPU — If present, model and VRAM (for compute-accelerated profiles)

These properties are registered as traits in OpenStack and can be used for scheduling — ensuring workloads are placed on hardware that matches their requirements.

Hardware Profiles

While the specific hardware available depends on what is installed in your rack, OPCP nodes typically fall into these categories:

Compute-Optimised

  • High core-count CPUs
  • Balanced RAM-to-CPU ratio
  • Suited for: application servers, containers, parallel processing

Memory-Optimised

  • Large RAM capacity
  • Suited for: in-memory databases, analytics, caching layers

Storage-Optimised

  • Multiple high-capacity drives (NVMe/SSD)
  • Suited for: data lakes, object storage, database servers

GPU-Accelerated

  • Dedicated GPU cards
  • Suited for: AI/ML training, rendering, scientific computing

You can view available hardware profiles through the Horizon dashboard or via CLI:

# List all nodes with their properties
openstack baremetal node list --long

# View traits of a specific node
openstack baremetal node show $NODE_ID --fields properties

Nova Flavors and Scheduling

In OpenStack, flavors define the resource template for instance deployment. In OPCP's bare metal context:

  • Flavors map to specific hardware profiles
  • When you deploy an instance with a given flavor, Nova schedules it on a node whose traits match
  • This ensures your workload lands on appropriate hardware
# List available flavors
openstack flavor list

# Show flavor details including required traits
openstack flavor show $FLAVOR_NAME

Choosing the Right Node Type

When planning your deployments, consider:

  • Workload requirements — Does it need more CPU, RAM, storage, or GPU?
  • Performance characteristics — NVMe storage for I/O-intensive workloads, high-memory for analytics
  • Availability — Check which profiles are available (some may already be in Active state)
  • Scalability — Plan for future growth by understanding what hardware is in the rack

Key Takeaways

  • Nodes in OPCP are physical bare metal servers managed by OpenStack Ironic
  • Hardware properties are automatically discovered when servers boot in the rack
  • Different hardware profiles (compute, memory, storage, GPU) serve different workloads
  • Traits and flavors ensure workloads are scheduled on matching hardware
  • No virtualisation overhead — you get the full dedicated hardware resources
