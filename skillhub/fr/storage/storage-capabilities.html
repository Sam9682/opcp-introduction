Capacités de Stockage

Intermédiaire 🇬🇧 English

Deux types de stockage sur OPCP

La plateforme OPCP fournit deux systèmes de stockage complémentaires, chacun répondant à des besoins différents :

  • CloudStore (S3) — Stockage objet S3-compatible pour les données non structurées (fichiers, médias, sauvegardes).
  • Ceph RBD — Stockage bloc haute performance pour les charges de travail structurées (bases de données, volumes de boot, applications nécessitant des disques persistants).

Pensez à CloudStore comme un vaste classeur pour des documents de toute taille, et à Ceph RBD comme des disques durs dédiés que vous attachez à vos serveurs — chacun optimisé pour son usage.

Capacité 1 : Évolutivité

L'évolutivité (ou scalabilité) désigne la capacité d'augmenter (ou de réduire) votre espace de stockage à la demande, sans interruption ni perturbation.

Analogie du monde réel : Imaginez un entrepôt dont les murs peuvent coulisser vers l'extérieur chaque fois que vous avez besoin de plus de place. Vous n'avez jamais à déménager dans un bâtiment plus grand — le vôtre s'agrandit simplement.

Évolutivité Ceph RBD

  • Volumes de 1 Go à 16 To — provisionnez exactement ce dont vous avez besoin.
  • Redimensionnement à chaud — augmentez la taille d'un volume sans le démonter ni arrêter la charge de travail. Aucun temps d'arrêt requis.
  • Les volumes restent attachés et opérationnels pendant les opérations de redimensionnement.

Évolutivité CloudStore (S3)

  • Le stockage objet évolue avec vos données — aucun pré-provisionnement requis.
  • Gérez les pics saisonniers sans engagements de capacité permanents.
  • Limité uniquement par la capacité physique de votre rack OPCP on-premise.

Capacité 2 : Redondance

La redondance signifie que vos données sont automatiquement copiées pour vous protéger contre les pannes matérielles.

Analogie du monde réel : Pensez-y comme garder trois copies de vos documents les plus importants dans trois coffres-forts différents au sein du même bâtiment sécurisé. Si l'un des coffres a un problème, les autres contiennent toujours vos données.

Ceph RBD : Triple réplication

  • 3 copies de chaque bloc de données sont maintenues à travers différents OSDs (Object Storage Daemons) dans le cluster Ceph.
  • Les données survivent aux pannes de disques ou de nœuds individuels — un disque cassé ne signifie pas des données perdues.
  • La réplication se fait automatiquement en arrière-plan sans intervention manuelle.
  • Toutes les données restent on-premise dans votre rack OPCP.

CloudStore (S3)

  • Configuration MonoAZ — les données sont stockées localement sur la plateforme OPCP.
  • La redondance est gérée au niveau de l'infrastructure au sein du rack.

Capacité 3 : Méthodes d'accès

Les méthodes d'accès sont les différentes façons dont vos applications et utilisateurs peuvent se connecter et interagir avec les données stockées.

Analogie du monde réel : Un entrepôt bien conçu dispose de plusieurs entrées — un quai de chargement pour les grandes livraisons, un accueil pour les petits retraits et une porte de coffre-fort pour les articles de grande valeur. Chaque entrée sert un objectif différent.

Méthodes d'accès disponibles

  • API S3 — Pour le stockage objet (CloudStore). Utilisez n'importe quel SDK ou outil S3-compatible (AWS CLI, boto3, s3cmd, etc.) pour gérer les buckets et objets.
  • API OpenStack Cinder — Pour le stockage bloc (Ceph RBD). Gérez les volumes, snapshots et attachements de manière programmatique.
  • Dashboard Horizon — Interface web visuelle pour gérer les deux types de stockage via le dashboard OpenStack.
  • CLI OpenStack — Interface en ligne de commande pour le scripting et l'automatisation des opérations de stockage.

Capacité 4 : Protection des données

La protection des données sur OPCP varie entre les deux types de stockage :

CloudStore (S3) — Chiffrement SSE-C

  • SSE-C (Server-Side Encryption with Customer-provided keys) est supporté.
  • Le client gère et fournit la clé de chiffrement à chaque requête.
  • Pas de chiffrement au repos par défaut — si vous avez besoin du chiffrement, vous devez implémenter SSE-C dans votre application.
  • Les données en transit peuvent être protégées via HTTPS.

Ceph RBD — Intégrité des données

  • Ceph gère l'intégrité des données nativement via des mécanismes de checksumming et d'auto-réparation.
  • La triple réplication assure la durabilité des données même en cas de panne matérielle.
  • Le cluster Ceph vérifie continuellement la cohérence des données entre les réplicas.

Important : Contrairement à l'offre cloud public, OPCP ne fournit pas de chiffrement automatique au repos pour le stockage S3. Si le chiffrement est une exigence, implémentez SSE-C dans votre couche applicative ou utilisez le chiffrement côté client avant l'envoi.

Niveaux de performance Ceph RBD

Ceph RBD propose trois niveaux de performance pour s'adapter à différentes charges de travail. Choisissez le niveau en fonction de l'intensité I/O de votre application :

Niveau IOPS Idéal pour
Standard 1 000 Charges de travail générales, stockage de fichiers, environnements de développement
High 3 000 Bases de données, charges transactionnelles, serveurs d'applications
Insane 7 500 Calcul haute performance, I/O intensif, analytics temps réel

Conseil pour les conversations clients : Commencez par comprendre le type de charge de travail. Une application web standard peut convenir au niveau Standard, mais une base de données transactionnelle (PostgreSQL, MySQL) bénéficiera significativement du niveau High. Réservez Insane pour les charges avec des besoins I/O élevés avérés.

Fonctionnalités avancées Ceph RBD

Au-delà du stockage bloc de base, Ceph RBD fournit des fonctionnalités puissantes pour une flexibilité opérationnelle :

  • Snapshots instantanés — Créez des snapshots ponctuels grâce à la technologie Copy-on-Write (CoW). La création du snapshot a un temps de copie initial nul — c'est instantané quelle que soit la taille du volume.
  • Clonage CoW — Créez de nouveaux volumes à partir de snapshots existants instantanément. Le clone partage les données avec le parent jusqu'à ce que des blocs soient modifiés, rendant l'opération extrêmement rapide et efficace en stockage.
  • Boot-from-volume — Démarrez les nœuds bare metal directement depuis des volumes Ceph RBD, permettant un déploiement OS flexible et un provisionnement rapide.
  • Redimensionnement à chaud — Augmentez la taille du volume pendant qu'il est monté et en cours d'utilisation. Aucun démontage ni temps d'arrêt requis.
  • Mirroring RBD — Réplication asynchrone entre clusters Ceph pour la reprise après sinistre. Permet la réplication entre sites OPCP pour la géo-redondance.

Documentation officielle : Pour des informations détaillées sur le stockage Ceph RBD sur OPCP, consultez le guide de présentation Ceph RBD.

Capacités en un coup d'œil

Points clés à retenir

  • OPCP offre deux types de stockage : CloudStore (stockage objet S3) et Ceph RBD (stockage bloc).
  • Évolutivité : les volumes Ceph RBD vont de 1 Go à 16 To avec redimensionnement à chaud ; CloudStore évolue automatiquement.
  • Redondance : Ceph RBD utilise la triple réplication à travers les OSDs ; toutes les données restent on-premise.
  • Accès : API S3 pour le stockage objet, API OpenStack Cinder pour le stockage bloc, plus dashboard et CLI.
  • Protection des données : SSE-C pour S3 (le client gère les clés, pas de chiffrement au repos par défaut) ; Ceph gère l'intégrité nativement.
  • Trois niveaux Ceph RBD : Standard (1 000 IOPS), High (3 000 IOPS), Insane (7 500 IOPS).
  • Fonctionnalités avancées : snapshots instantanés, clonage CoW, boot-from-volume, mirroring RBD pour la DR.
