Premiers pas avec CloudStore

Intermédiaire

Objectif

Ce guide vous montre comment vous connecter à l'interface de gestion de votre CloudStore, comprendre ses concepts clés, et effectuer les premières opérations telles que la création de comptes et le déploiement de services.

CloudStore est un framework d'infrastructure de haut niveau déployé au-dessus de la plateforme OPCP (On-Premise Cloud Platform). Il fournit des services de base pour aider les fournisseurs cloud à déployer et gérer des solutions cloud-natives pour leurs clients via une plateforme basée sur un catalogue de services (marketplace).

Le contenu ci-dessous s'appuie sur la documentation officielle OVHcloud : Getting started with your CloudStore.

Prérequis

  • L'URL de l'interface de gestion CloudStore, fournie lors de la livraison du service.
  • Les identifiants de connexion (nom d'utilisateur et mot de passe) fournis lors de la livraison du service. Ces identifiants sont gérés par Keycloak, la solution de gestion des identités et des accès utilisée par la plateforme.

Connexion à CloudStore

Naviguez vers l'URL fournie pour votre instance CloudStore. Une page de connexion s'affiche.

Cliquez sur le bouton de connexion pour être redirigé vers la page d'authentification Keycloak. Deux options d'authentification sont disponibles :

  • Connexion directe — Saisir vos identifiants dans le formulaire Keycloak.
  • OPCP-SSO — S'authentifier via le Keycloak fédéré OPCP Core. Cette option permet aux utilisateurs déjà enregistrés dans OPCP Core de se connecter sans gérer un jeu d'identifiants séparé.

Une fois authentifié, l'interface obtient un jeton d'accès OIDC utilisé pour toutes les opérations suivantes.

Le tableau de bord CloudStore

Après connexion, vous accédez au tableau de bord CloudStore. Depuis celui-ci, vous pouvez atteindre les zones suivantes :

  • Catalogue de services — Parcourir et activer les services disponibles (ex : VCF).
  • Comptes (Accounts) — Créer et gérer les comptes locataires pour vos clients ou équipes internes.
  • Contrôleurs et Apps — Déployer et gérer les composants d'infrastructure de chaque service.
  • Gestion IAM — Configurer les utilisateurs et permissions dans Keycloak.

Concepts clés

Les personas

CloudStore distingue deux audiences principales :

  • Fournisseurs cloud (IT admins, Service admins) — Clients OVHcloud qui exploitent la plateforme. Ils provisionnent l'infrastructure, déploient des services et gèrent les comptes.
  • Utilisateurs cloud (utilisateurs Landing Zone Manager) — Clients des fournisseurs cloud qui consomment les services déployés pour eux via la Landing Zone.
Rôle Responsabilités
IT admin Créer des comptes, activer des services, déployer des apps
Service admin Gérer un service spécifique, déployer son contrôleur et ses apps
Account admin Gérer la configuration de son compte
Utilisateur Landing Zone Manager Accéder aux apps via la Landing Zone

Le modèle contrôleur / app

Chaque service dans CloudStore suit une architecture contrôleur / app :

  • Le contrôleur (controlplane) est déployé en premier. Il gère le cycle de vie des apps et l'orchestration inter-locataires. Un seul contrôleur peut gérer plusieurs apps à travers différents comptes.
  • Les apps (dataplane) sont des workloads déployés pour un compte spécifique. Chaque app est isolée dans un seul compte et ne peut pas être partagée entre comptes.

Ce modèle permet aux fournisseurs cloud d'offrir le même service à plusieurs clients, chacun obtenant sa propre instance d'app isolée tout en partageant la même infrastructure de contrôle.

Créer un compte

Un compte représente une entreprise ou un département. Chaque compte possède son propre realm Keycloak, garantissant une isolation IAM complète. Les comptes doivent être créés avant de déployer des apps, car chaque app est toujours rattachée à un compte.

Étapes

  1. Depuis le tableau de bord CloudStore, naviguez vers la section Accounts.
  2. Cliquez sur Create an account.
  3. Remplissez les champs requis : nom du compte, nom complet de l'administrateur et adresse email de l'administrateur.
  4. Soumettez le formulaire.

La plateforme crée automatiquement :

  • Un realm Keycloak dédié nommé account-{name}.
  • Un utilisateur administrateur avec le rôle account-admin.
  • Un mot de passe temporaire (l'admin du compte devra le modifier à la première connexion).
  • Un client landing-zone pour l'accès des utilisateurs Landing Zone Manager.

Déployer un service

Le déploiement d'un service se fait en deux étapes : d'abord déployer le contrôleur, puis déployer une ou plusieurs apps pour des comptes spécifiques.

Étape 1 — Déployer un contrôleur

  1. Naviguez vers le Catalogue de services depuis le tableau de bord.
  2. Sélectionnez le service à activer.
  3. Cliquez sur Activate the service.
  4. Choisissez la version et configurez les propriétés requises.
  5. Sélectionnez les hôtes sur lesquels le contrôleur sera déployé.
  6. Soumettez le formulaire.

Note : Le déploiement du contrôleur est asynchrone. L'interface confirme que le déploiement a démarré, mais le provisionnement s'effectue en arrière-plan via Kubernetes et Terraform. Vous pouvez surveiller l'état du déploiement depuis la page des contrôleurs.

Étape 2 — Déployer une app

Une fois le contrôleur actif et au moins un compte existant :

  1. Naviguez vers la page du contrôleur.
  2. Cliquez sur Deploy an app.
  3. Sélectionnez le compte cible.
  4. Choisissez la version et configurez les propriétés requises.
  5. Sélectionnez les hôtes pour le déploiement de l'app.
  6. Soumettez le formulaire.

Lors du déploiement d'une app, la plateforme crée automatiquement les ressources Keycloak nécessaires (client-id, rôles et groupes) dans le realm du compte cible, garantissant que seuls les utilisateurs autorisés de ce compte puissent accéder à l'app.

Dimensionner la capacité

Vous pouvez ajouter ou retirer des hôtes d'un contrôleur ou d'une app déployé(e) pour ajuster la capacité :

  1. Naviguez vers la page du contrôleur ou de l'app.
  2. Cliquez sur Expand capacity.
  3. Sélectionnez les hôtes à ajouter.
  4. Soumettez le formulaire.

L'opération de mise à l'échelle est asynchrone. Kubernetes réconcilie la configuration et provisionne les ressources sur les hôtes mis à jour.

Authentification et niveaux d'accès

CloudStore utilise un modèle de fédération Keycloak à plusieurs couches qui reflète l'architecture de la plateforme :

Couche Instance Keycloak Utilisateurs Rôle
L1 OPCP Core Keycloak Opérateurs DC, Super admins Identité au niveau infrastructure
L2 CloudStore Keycloak IT admins, Service admins Gestion de la plateforme
L3 Realms Keycloak par compte Utilisateurs Landing Zone Manager Accès aux applications
  • Keycloak L2 est fédéré avec L1 (OPCP Core). Les droits accordés sur les projets OpenStack au niveau L1 sont propagés vers L2.
  • Keycloak L3 est une instance indépendante gérée par l'API CloudStore. Chaque compte obtient son propre realm isolé.

Gérer l'IAM sur Keycloak CloudStore (L2)

Pour gérer les utilisateurs, rôles et groupes sur le Keycloak CloudStore (L2), attribuez d'abord le rôle cloudstore-admins à votre utilisateur dans le Keycloak OPCP Core (L1) :

  1. Connectez-vous à la console d'administration Keycloak OPCP Core (L1).
  2. Naviguez vers l'utilisateur concerné.
  3. Dans l'onglet Role mappings, attribuez le rôle client cloudstore-admins.

La Landing Zone

La Landing Zone est l'interface destinée aux utilisateurs cloud (utilisateurs Landing Zone Manager). Elle fournit une vue simplifiée des apps déployées pour leur compte.

Les utilisateurs s'authentifient via le realm Keycloak spécifique à leur compte (L3) et ne peuvent accéder qu'aux apps déployées pour ce compte. La Landing Zone récupère la liste des apps accessibles et les filtre selon les permissions de l'utilisateur.

Points clés à retenir

  • CloudStore est un framework d'infrastructure déployé au-dessus d'OPCP, permettant aux fournisseurs cloud de gérer des solutions cloud-natives via un catalogue de services.
  • L'authentification se fait via Keycloak avec un modèle fédéré à 3 couches (L1 infrastructure, L2 plateforme, L3 comptes).
  • L'architecture repose sur le modèle contrôleur / app : un contrôleur unique orchestre plusieurs apps isolées par compte.
  • Les comptes représentent des locataires isolés avec leur propre realm Keycloak pour l'IAM.
  • Les déploiements (contrôleurs et apps) sont asynchrones, gérés par Kubernetes et Terraform en arrière-plan.
  • La Landing Zone fournit une interface simplifiée aux utilisateurs finaux des fournisseurs cloud.
