Understanding the Node Lifecycle

In OPCP, a node represents the configuration of a physical server (bare metal) in the OPCP rack, managed by OpenStack Ironic. Nodes are different from instances — an instance represents the operating system deployed on a node.

Node discovery is automatic: when a physical server boots in the rack, the OPCP control plane auto-discovers its hardware properties and traits. Understanding the node states helps you manage your bare metal infrastructure effectively.

Reference: OVHcloud OPCP Node Lifecycle Documentation

Lifecycle States at a Glance

Node States

Each node passes through a series of states during its lifecycle. Here are the key states:

State Description
Enroll First state when a node is auto-discovered by OPCP. Not yet verified. Must be moved to Manageable manually.
Verifying Transitional state from Enroll to Manageable. Ironic verifies that it can manage the node.
Manageable Node is verified and managed by Ironic, but not yet ready for installation. Must be moved to Available.
Available Node is ready to be installed with an instance.
Deploying / Wait call-back Transitional state during the installation of an instance on the node.
Active Node has an active instance running. This is the normal operational state.
Cleaning / Clean-wait Transitional state when an instance is deleted or the node leaves Manageable. Disks are formatted during this phase.

State Transitions

Nodes progress through states via specific operations:

Enroll → Manageable

After a node is auto-discovered, an administrator must explicitly move it to Manageable state. During this transition, the node enters the Verifying state where Ironic confirms it can manage the hardware.

openstack baremetal node manage $NODE_ID

Manageable → Available

Once verified, the node must be provided (made available) for installation. During this transition, a Cleaning phase may occur where disks are formatted.

openstack baremetal node provide $NODE_ID

Available → Active

When an instance is deployed on the node, it transitions through Deploying / Wait call-back and then reaches the Active state.

Active → Available

When an instance is deleted, the node passes through the Cleaning state (disks are formatted) and returns to Available.

Maintenance Mode

Any node can be placed in maintenance mode to prevent operations from being performed on it. This is useful for hardware troubleshooting or planned interventions.

Set Maintenance Mode

openstack baremetal node maintenance set $NODE_ID --reason "Hardware inspection required"

Exit Maintenance Mode

openstack baremetal node maintenance unset $NODE_ID

Monitoring Node Status

You can check the status of your nodes through two methods:

Via Horizon Dashboard

Navigate to Admin > System > Ironic Bare Metal Provisioning to view the current state of all nodes.

Via CLI

# List all nodes and their states
openstack baremetal node list

# Show detailed information about a specific node
openstack baremetal node show $NODE_ID

Automatic Node Discovery

When a new physical server boots in the OPCP rack, the control plane automatically:

  • Detects the server via the OOB (Out-of-Band) management network
  • Discovers hardware properties (CPU, RAM, storage, network interfaces)
  • Identifies hardware traits and capabilities
  • Registers the node in the Enroll state

No manual registration is required — the platform handles discovery automatically.

Key Takeaways

  • A node represents a physical server configuration, distinct from the instance (OS) running on it
  • Node discovery is automatic when hardware boots in the rack
  • The lifecycle follows: Enroll → Verifying → Manageable → Available → Deploying → Active
  • Cleaning occurs when instances are deleted (disks are formatted)
  • Maintenance mode can be set on any node to prevent operations
  • Status can be monitored via Horizon (Admin > System > Ironic) or CLI
