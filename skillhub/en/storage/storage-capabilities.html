Two Storage Types on OPCP

The OPCP platform provides two complementary storage systems, each serving different needs:

  • CloudStore (S3) — S3-compatible object storage for unstructured data (files, media, backups).
  • Ceph RBD — High-performance block storage for structured workloads (databases, boot volumes, applications requiring persistent disks).

Think of CloudStore as a vast filing cabinet for documents of any size, and Ceph RBD as dedicated hard drives that you attach to your servers — each optimised for its purpose.

Capability 1: Scalability

Scalability means the ability to grow (or shrink) your storage space on demand, without downtime or disruption.

Real-world analogy: Imagine a warehouse where walls can slide outward whenever you need more room. You never have to move to a bigger building — your current one simply expands.

Ceph RBD scalability

  • Volume sizes from 1 GB to 16 TB — provision exactly what you need.
  • Live resize — increase a volume's size without unmounting or stopping the workload. No downtime required.
  • Volumes remain attached and operational during resize operations.

CloudStore (S3) scalability

  • Object storage scales with your data — no pre-provisioning required.
  • Handle seasonal spikes without permanent capacity commitments.
  • Limited only by the physical capacity of your on-premise OPCP rack.

Capability 2: Redundancy

Redundancy means your data is automatically copied to protect against hardware failures.

Real-world analogy: Think of it like keeping three copies of your most important documents in three different safes within the same secure building. If one safe has a problem, the others still have your data.

Ceph RBD: Triple replication

  • 3 copies of every data block are maintained across different OSDs (Object Storage Daemons) in the Ceph cluster.
  • Data survives individual disk or node failures — a broken drive doesn't mean lost data.
  • Replication happens automatically in the background with no manual intervention.
  • All data remains on-premise within your OPCP rack.

CloudStore (S3)

  • MonoAZ configuration — data is stored locally on the OPCP platform.
  • Redundancy is handled at the infrastructure level within the rack.

Capability 3: Access Methods

Access methods are the different ways your applications and users can connect to and interact with stored data.

Real-world analogy: A well-designed warehouse has multiple entrances — a loading dock for large deliveries, a front desk for small pickups, and a secure vault for high-value items. Each entrance serves a different purpose.

Available access methods

  • S3 API — For object storage (CloudStore). Use any S3-compatible SDK or tool (AWS CLI, boto3, s3cmd, etc.) to manage buckets and objects.
  • OpenStack Cinder API — For block storage (Ceph RBD). Manage volumes, snapshots, and attachments programmatically.
  • Horizon Dashboard — Web-based visual interface for managing both storage types through the OpenStack dashboard.
  • OpenStack CLI — Command-line interface for scripting and automation of storage operations.

Capability 4: Data Protection

Data protection on OPCP varies between the two storage types:

CloudStore (S3) — SSE-C encryption

  • SSE-C (Server-Side Encryption with Customer-provided keys) is supported.
  • The client manages and provides the encryption key with each request.
  • No at-rest encryption by default — if you need encryption, you must implement SSE-C in your application.
  • Data in transit can be protected via HTTPS.

Ceph RBD — Data integrity

  • Ceph handles data integrity natively through checksumming and self-healing mechanisms.
  • Triple replication ensures data durability even when hardware fails.
  • The Ceph cluster continuously verifies data consistency across replicas.

Important: Unlike the public cloud offering, OPCP does not provide automatic at-rest encryption for S3 storage. If encryption is a requirement, implement SSE-C in your application layer or use client-side encryption before uploading.

Ceph RBD Performance Tiers

Ceph RBD offers three performance tiers to match different workload requirements. Choose the tier based on the I/O intensity of your application:

Tier IOPS Best For
Standard 1,000 General workloads, file storage, development environments
High 3,000 Databases, transactional workloads, application servers
Insane 7,500 High-performance computing, intensive I/O, real-time analytics

Tip for customer conversations: Start by understanding the workload type. A standard web application might be fine on the Standard tier, but a transactional database (PostgreSQL, MySQL) will benefit significantly from the High tier. Reserve Insane for workloads with proven high I/O demands.

Ceph RBD Advanced Features

Beyond basic block storage, Ceph RBD provides powerful features for operational flexibility:

  • Instant snapshots — Create point-in-time snapshots using Copy-on-Write (CoW) technology. Snapshot creation has zero initial copy time — it's instantaneous regardless of volume size.
  • CoW cloning — Create new volumes from existing snapshots instantly. The clone shares data with the parent until blocks are modified, making it extremely fast and storage-efficient.
  • Boot-from-volume — Boot bare metal nodes directly from Ceph RBD volumes, enabling flexible OS deployment and rapid provisioning.
  • Live resize — Increase volume size while the volume is mounted and in use. No unmounting or downtime required.
  • RBD mirroring — Asynchronous replication between Ceph clusters for disaster recovery. Enables replication between OPCP sites for geo-redundancy.

Official documentation: For detailed information about Ceph RBD storage on OPCP, refer to the Ceph RBD overview guide.

Capabilities at a Glance

Key Takeaways

  • OPCP offers two storage types: CloudStore (S3 object storage) and Ceph RBD (block storage).
  • Scalability: Ceph RBD volumes range from 1 GB to 16 TB with live resize; CloudStore scales automatically.
  • Redundancy: Ceph RBD uses triple replication across OSDs; all data stays on-premise.
  • Access: S3 API for object storage, OpenStack Cinder API for block storage, plus dashboard and CLI.
  • Data protection: SSE-C for S3 (client manages keys, no at-rest encryption by default); Ceph handles integrity natively.
  • Three Ceph RBD tiers: Standard (1,000 IOPS), High (3,000 IOPS), Insane (7,500 IOPS).
  • Advanced features: instant snapshots, CoW cloning, boot-from-volume, RBD mirroring for DR.
