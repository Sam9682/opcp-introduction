Premiers pas avec OPCP

Débutant 🇬🇧 English

Présentation

Cette leçon résume les premières étapes nécessaires pour accéder et configurer votre environnement OPCP. Elle couvre la connexion aux interfaces de gestion et l'installation du contrôleur qui constitue la base de la plateforme.

Le contenu ci-dessous s'appuie sur la documentation officielle OVHcloud : Getting started with your OPCP et How to install a controller.

Partie 1 — Accéder aux interfaces OPCP

Prérequis

  • L'URL de l'interface de gestion fournie lors de la livraison du service
  • Les identifiants de connexion livrés avec le service

Connexion

Utilisez l'URL fournie lors de la livraison pour accéder à la page de connexion OPCP, propulsée par Keycloak. Après authentification, vous arrivez sur le tableau de bord produit.

Ce que le tableau de bord propose

  • IAM (Keycloak) — gérez les utilisateurs et les paramètres d'authentification via le lien IAM sous votre identifiant.
  • OpenStack Horizon — une interface web pour gérer l'ensemble de l'infrastructure OpenStack : créer et arrêter des instances, configurer les réseaux et gérer l'accessibilité.
  • Points d'accès API — accès à Keystone (identité), Glance (images), Nova (calcul), Neutron (réseau) et Ironic (gestion bare-metal) pour l'automatisation.

Sections clés d'Horizon

  • Vue d'ensemble — affiche les quotas de ressources (calcul et réseau) et l'historique d'utilisation.
  • Accès API — liste tous les points d'accès des services pour la communication API directe.
  • Calcul > Instances — lister et gérer les serveurs dédiés configurés en tant qu'instances.
  • Calcul > Images — gérer les images d'OS (personnalisées ou pré-construites) utilisées pour provisionner les instances. Les images doivent être compatibles avec les pilotes matériels de votre OPCP.
  • Calcul > Paires de clés — importer ou créer des paires de clés SSH pour l'authentification aux instances après installation.
  • Réseau — créer et gérer des réseaux partagés ou isolés. La configuration est gérée via cette interface ou via l'API Neutron, et les commutateurs sont automatiquement configurés.

Partie 2 — Installation du contrôleur OPCP

Objectif

Le contrôleur est le nœud de gestion qui exécute les services OpenStack de votre OPCP. Il est installé à partir d'une image ISO basée sur Debian, fournie par OVHcloud via un bucket S3 en lecture seule.

Prérequis

  • Un serveur physique dédié à l'hébergement du contrôleur
  • Un accès en lecture seule au bucket S3 de livraison OPCP (endpoint, nom du bucket, région, version)
  • Une clé d'accès S3 et une clé secrète dédiées (lecture seule, limitées au préfixe de livraison)
  • Une clé USB bootable ou un périphérique de média virtuel
  • Un accès à la console de gestion à distance du serveur (IPMI, iDRAC, iLO)
  • Au moins 2 disques physiques de taille similaire pour le RAID 1
  • Un câble réseau connectant la première interface du serveur à votre réseau
  • Adresse IP, masque de sous-réseau, passerelle et serveurs DNS pour le réseau d'accès au contrôleur

Étapes d'installation

  1. Télécharger et vérifier l'image — récupérer l'ISO et sa somme de contrôle SHA-256 depuis le bucket S3 avec s3cmd ou des requêtes curl signées, puis vérifier la somme de contrôle et écrire l'ISO sur le support d'amorçage.
  2. Câbler le serveur — connecter uniquement la première interface réseau à votre réseau.
  3. Démarrer l'installateur — amorcer depuis le support et sélectionner « Auto Install » dans le menu GRUB.
  4. Sélectionner les disques — choisir au moins 2 disques (idéalement identiques) pour le RAID 1. L'installateur crée automatiquement la configuration RAID et la disposition LVM.
  5. Configurer le réseau — sélectionner l'interface connectée, choisir « Static », et saisir l'IP, le masque, la passerelle et les DNS.
  6. Vérifier l'accès — après le premier démarrage, confirmer la connectivité SSH vers l'IP du contrôleur et valider que le nœud peut atteindre les ressources réseau nécessaires.
  7. Ajuster les volumes LVM — redimensionner les volumes logiques (spare, home, root, tmp, var) en fonction de la capacité des disques et des besoins de la charge de travail.

Étapes suivantes

Une fois le contrôleur opérationnel et accessible, vous pouvez passer à la configuration des nœuds, à la mise en place des réseaux et au déploiement de vos premières instances via Horizon ou les API OpenStack.
