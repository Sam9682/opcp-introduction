Resource Management in OPCP

Resource allocation in OPCP is managed through OpenStack services, each responsible for a specific resource domain. Since OPCP is a bare metal platform, resources correspond to physical hardware rather than virtual slices.

The platform provides a unified interface (Horizon dashboard + APIs) to manage compute, network, and storage resources across your on-premise rack.

Reference: OVHcloud OPCP Getting Started Documentation

OpenStack Services for Resource Management

Resource Type OpenStack Service What It Manages
Compute Nova + Ironic Bare metal server provisioning, instance lifecycle, scheduling
Network Neutron Networks, subnets, ports, security groups, floating IPs, trunks
Block Storage Ceph RBD Persistent block volumes attached to instances
Object Storage S3-compatible (CloudStore) Unstructured data: backups, logs, media files
Image Glance OS images for bare metal deployment

Compute Resources (Nova + Ironic)

Compute in OPCP means bare metal servers. Resources are allocated by deploying instances on available nodes:

  • Allocation model — One instance per physical node (no overcommit since it's bare metal)
  • Scheduling — Nova schedules instances on nodes matching the requested flavor's traits
  • Quotas — Visible in Project > Overview: max instances, vCPUs, and RAM
# Check current compute quota usage
openstack quota show

# List available nodes ready for deployment
openstack baremetal node list --provision-state available

Network Resources (Neutron)

Neutron manages all networking in OPCP, and physical switches are auto-configured from the OpenStack state:

  • Networks and subnets — Logical networks mapped to physical VLANs
  • Ports — Network attachment points for instances
  • Security groups — Firewall rules applied at the port level
  • Floating IPs — External-facing IP addresses
  • Trunks — Multi-VLAN connectivity for a single port
# List networks
openstack network list

# Create a network
openstack network create my-network

# Create a subnet
openstack subnet create --network my-network --subnet-range 192.168.1.0/24 my-subnet

Storage Resources

Block Storage (Ceph RBD)

Persistent block volumes for instances, powered by Ceph:

  • Volumes can be attached/detached from instances
  • Data persists independently of the instance lifecycle
  • Replicated across the Ceph cluster for durability

Object Storage (S3-compatible CloudStore)

S3-compatible storage for unstructured data:

  • Backup endpoint (TCP/443) — Infrastructure backup storage
  • Metrics endpoint (TCP/443) — Long-term metrics storage
  • Accessible via standard S3 APIs and tools

Quota Management

Quotas in OPCP define the maximum resources available to a project. View them in Project > Overview:

Category Quota Items
Compute Instances, vCPUs, RAM
Network Floating IPs, Security Groups, Networks, Ports
Storage Volumes, total volume storage (GB), snapshots

Since OPCP is on-premise, quotas represent your physical hardware capacity. Contact your OVHcloud representative to discuss quota adjustments.

Key Takeaways

  • Resource allocation in OPCP is managed via OpenStack services: Nova/Ironic (compute), Neutron (network), Ceph RBD (block storage), CloudStore (object storage)
  • Compute allocation is bare metal — one instance per physical node, no overcommit
  • Network configuration in OpenStack automatically drives physical switch configuration
  • Block storage is provided by Ceph RBD with replication for durability
  • S3-compatible object storage is available for backups and metrics
  • Quotas represent physical capacity and are visible in Project > Overview
