LACP, Trunk & RAID

Intermédiaire

Présentation

Cette leçon couvre trois capacités d'infrastructure disponibles dans OPCP et comment elles sont configurées avec les outils de la plateforme. Dans OPCP, ces fonctionnalités sont gérées via les API OpenStack et l'outil opcp-cli — les switchs réseau sont automatiquement configurés en fonction de vos paramètres OpenStack.

Principe clé : La configuration réseau dans OPCP est pilotée par Horizon/API (Neutron). Les switchs physiques sont automatiquement configurés à partir des informations définies dans OpenStack — aucun accès manuel aux switchs n'est nécessaire.

LACP — Agrégation de Liens

Ce que C'est

LACP (Link Aggregation Control Protocol) combine plusieurs interfaces réseau en un seul lien logique, offrant une bande passante accrue et une protection contre les pannes.

En une phrase : LACP combine plusieurs connexions réseau en un seul lien plus rapide et plus fiable — comme ajouter des voies supplémentaires à une autoroute.

Fonctionnement dans OPCP

La configuration LACP dans OPCP est gérée via l'outil opcp-cli ou l'API OpenStack :

  • Les interfaces bond sont configurées au niveau du nœud lors du provisionnement
  • La configuration LACP côté switch est appliquée automatiquement par la plateforme
  • Aucune configuration manuelle des switchs n'est nécessaire
# La configuration du bond LACP est gérée via opcp-cli
# La plateforme gère la configuration côté hôte et côté switch

Bénéfices

  • Bande passante accrue — Plusieurs liens agrégés en une seule connexion logique
  • Haute disponibilité — Si un lien tombe, le trafic continue sur les liens restants
  • Pas de point unique de défaillance — Redondance au niveau de l'interface réseau
  • Configuration automatique des switchs — La plateforme configure les switchs en conséquence

Trunk — Organisation du Trafic Réseau

Ce que C'est

Un trunk réseau permet à un seul port physique de transporter le trafic de plusieurs réseaux (VLANs) simultanément. Dans OPCP, le trunking est géré via OpenStack Neutron.

En une phrase : Le trunking organise le trafic réseau en canaux séparés sur une seule connexion — comme trier le courrier dans différentes boîtes aux lettres à la même adresse.

Fonctionnement dans OPCP

La configuration des ports trunk est gérée via l'API Neutron ou le tableau de bord Horizon :

  • Créer des ports trunk dans Neutron pour transporter plusieurs VLANs sur un seul port physique
  • Ajouter des sous-ports au trunk pour chaque réseau/VLAN
  • La configuration trunk physique des switchs est appliquée automatiquement depuis les paramètres OpenStack
# Créer un port trunk via le CLI OpenStack
openstack network trunk create --parent-port $PARENT_PORT my-trunk

# Ajouter un sous-port au trunk
openstack network trunk set --subport port=$SUB_PORT,segmentation-type=vlan,segmentation-id=100 my-trunk

# Lister les trunks
openstack network trunk list

Bénéfices

  • Isolation réseau — Différentes charges de travail ou tenants sur des VLANs séparés
  • Utilisation efficace des ports — Plusieurs réseaux sur une seule connexion physique
  • Frontières de sécurité — Le trafic sensible est isolé du trafic général
  • Configuration automatique des switchs — Neutron pilote la configuration trunk des switchs physiques

RAID Logiciel — Protection des Données

Ce que C'est

Le RAID logiciel (Redundant Array of Independent Disks) distribue les données sur plusieurs disques pour la protection contre les pannes de disques. Dans OPCP, le RAID logiciel est configuré lors du provisionnement du nœud.

En une phrase : Le RAID protège les données en les répartissant sur plusieurs disques — comme conserver des copies de sauvegarde de documents importants dans des classeurs séparés.

Fonctionnement dans OPCP

La configuration du RAID logiciel fait partie du processus de déploiement d'instance :

  • Le niveau RAID est sélectionné lors du provisionnement du nœud (via les templates de déploiement ou les métadonnées d'instance)
  • La configuration est appliquée par Ironic pendant la phase de déploiement
  • Configurations courantes : RAID 1 (miroir), RAID 5 (striping avec parité), RAID 10 (stripes en miroir)
# La configuration RAID est définie dans le template de déploiement du nœud
# ou via l'interface RAID d'Ironic lors du provisionnement
openstack baremetal node set $NODE_ID \
  --target-raid-config '{"logical_disks": [{"size_gb": "MAX", "raid_level": "1", "is_root_volume": true}]}'

# Déclencher la configuration RAID (étape de nettoyage)
openstack baremetal node clean $NODE_ID \
  --clean-steps '[{"interface": "raid", "step": "create_configuration"}]'

Bénéfices

  • Sécurité des données — Les données survivent aux pannes de disques individuels
  • Fonctionnement continu — Le système continue de fonctionner même lorsqu'un disque tombe en panne
  • Configurable au provisionnement — Choisir le bon niveau RAID pour chaque charge de travail
  • Reconstruction automatique — Lorsqu'un disque défaillant est remplacé, les données sont reconstruites automatiquement

Comparaison Rapide

Fonctionnalité Méthode de Configuration Outil Bénéfice Clé
LACP Configuration du bond au niveau nœud opcp-cli / API Bande passante + redondance
Trunk Ports trunk avec sous-ports par VLAN API Neutron / Horizon Isolation réseau + efficacité
RAID Logiciel Défini lors du provisionnement du nœud Ironic (templates de déploiement) Protection des données + disponibilité

Points Clés à Retenir

  • LACP est configuré via opcp-cli ou l'API — les switchs sont auto-configurés par la plateforme
  • Les ports trunk sont gérés via OpenStack Neutron — aucun accès manuel aux switchs n'est nécessaire
  • Le RAID logiciel est configuré lors du provisionnement du nœud via Ironic
  • Toute la configuration réseau est pilotée par OpenStack — les switchs physiques suivent automatiquement
  • La plateforme élimine le besoin de configuration manuelle des switchs
