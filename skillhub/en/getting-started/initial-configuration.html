Initial Configuration

Beginner

Overview

After your OPCP platform has been deployed on-premise and you have received your access credentials, there are a few configuration steps to complete before your environment is fully operational.

OPCP is an on-premise platform — it runs in your own facility. After deployment, you connect via the URL defined during delivery and log in through the Keycloak authentication page to access the dashboard.

Reference: OVHcloud OPCP Getting Started Documentation

Step 1: Explore the Horizon Dashboard

Once logged in via Keycloak, you access the OpenStack Horizon dashboard — the primary interface for managing your OPCP infrastructure. The dashboard provides access to your platform's services: IAM (Keycloak) for user management, and the OpenStack APIs (Keystone, Glance, Nova, Neutron, Ironic).

Key areas to explore:

  • Project > Overview — View your quota limits: Compute (instances, vCPUs, RAM), Network (floating IPs, security groups, networks, ports)
  • Project > API Access — Lists the 10 available services with their endpoint URLs
  • Compute > Instances — List and manage your dedicated bare metal servers
  • Compute > Images — Available OS images for deployment
  • Network > Networks — List of available networks
  • Network > Topology — Visual representation of your network architecture

Important: OS images must match hardware drivers (bare metal drivers, not qemu/kvm virtual drivers).

Step 2: Understand Your Quotas

Your OPCP platform has defined resource quotas visible in Project > Overview. These set the boundaries for what you can deploy:

  • Compute quotas — Maximum number of instances, vCPUs, and RAM allocation
  • Network quotas — Maximum floating IPs, security groups, networks, and ports

These quotas represent the physical capacity of your on-premise rack. If you need to adjust them, contact your OVHcloud representative.

Step 3: Network Configuration

Network configuration in OPCP is driven by Horizon/API (Neutron). A key feature of the platform is that network switches are automatically configured based on the information you set in OpenStack.

This means:

  • You define networks and ports in Horizon or via the Neutron API
  • The physical switch configuration is applied automatically — no manual switch configuration needed
  • VLANs and trunk ports are managed through the OpenStack abstraction layer

Navigate to Network > Networks to see available networks, and Network > Topology for a visual overview of your network architecture.

Step 4: SSH Key Management

Before deploying instances, set up your SSH keys for secure access to bare metal nodes:

  • Navigate to Compute > Key Pairs
  • Import your existing public SSH key or create a new key pair
  • Key pairs will be injected during instance provisioning for secure access

Step 5: User Access via Keycloak

User management in OPCP is handled by the embedded Keycloak identity service (IAM). Access Keycloak from the dashboard to:

  • Create user accounts for your team members
  • Define roles and permissions
  • Optionally integrate with LDAP/Active Directory (TCP/636 LDAPS) for centralised identity management

Three levels of access are typically configured:

  • Administrator — Full access to all settings and services
  • Operator — Can manage services and deploy instances
  • Read-only — Can view information but cannot make changes

Configuration Complete

Once these steps are done, your OPCP environment is ready for deploying bare metal instances. Here is a quick recap:

  1. Explored the Horizon dashboard and understood available services
  2. Reviewed your resource quotas (Compute and Network)
  3. Understood that network switches are auto-configured from OpenStack
  4. Set up SSH key pairs for secure instance access
  5. Configured user access via Keycloak IAM

From here, you can explore the Node Lifecycle section to learn how bare metal nodes are managed, or jump to Technical Operations for deploying your first instance.
