Getting Started with OPCP

Beginner 🇫🇷 Français

Overview

This lesson provides a summary of the first steps required to access and configure your OPCP environment. It covers logging in to the management interfaces and installing the controller that forms the foundation of the platform.

The content below is based on the official OVHcloud documentation for Getting started with your OPCP and How to install a controller.

Part 1 — Accessing Your OPCP Interfaces

Prerequisites

  • The URL of the management interface provided at service delivery
  • Login credentials delivered with the service

Logging In

Use the URL provided during delivery to reach the OPCP login page, which is powered by Keycloak. After authenticating, you land on the product dashboard.

What the Dashboard Provides

  • IAM (Keycloak) — manage users and authentication settings via the IAM link under your login name.
  • OpenStack Horizon — a web interface for managing the entire OpenStack infrastructure: creating and stopping instances, configuring networks, and managing accessibility.
  • API endpoints — access to Keystone (identity), Glance (images), Nova (compute), Neutron (network), and Ironic (bare-metal management) for automation.

Key Horizon Sections

  • Overview — displays resource quotas (compute and network) and usage history.
  • API Access — lists all service endpoints for direct API communication.
  • Compute > Instances — list and manage dedicated servers configured as instances.
  • Compute > Images — manage OS images (custom or pre-built) used to provision instances. Images must be compatible with the hardware drivers of your OPCP.
  • Compute > Key Pairs — import or create SSH key pairs for authenticating to instances after installation.
  • Network — create and manage shared or isolated networks. Configuration is handled via this interface or through the Neutron API, and switches are automatically configured.

Part 2 — Installing the OPCP Controller

Purpose

The controller is the management node that runs the OpenStack services for your OPCP. It is installed from a Debian-based ISO image provided by OVHcloud via a read-only S3 bucket.

Prerequisites

  • A physical server dedicated to hosting the controller
  • Read-only access to the OPCP delivery S3 bucket (endpoint, bucket name, region, version)
  • A dedicated S3 access key and secret key (read-only, scoped to the delivery prefix)
  • A bootable USB key or virtual media device
  • Access to the server's remote management console (IPMI, iDRAC, iLO)
  • At least 2 physical disks of similar size for RAID 1
  • One network cable connecting the server's first interface to your network
  • IP address, subnet mask, gateway, and DNS servers for the controller access network

Installation Steps

  1. Download and verify the image — retrieve the ISO and its SHA-256 checksum from the S3 bucket using s3cmd or signed curl requests, then verify the checksum and write the ISO to your boot media.
  2. Cable the server — connect only the first network interface to your network.
  3. Boot the installer — boot from the media and select "Auto Install" in the GRUB menu.
  4. Select disks — choose at least 2 disks (ideally identical) for RAID 1. The installer creates the RAID and LVM layout automatically.
  5. Configure network — select the connected interface, choose "Static", and enter the IP, mask, gateway, and DNS.
  6. Verify access — after first boot, confirm SSH connectivity to the controller IP and validate that the node can reach required network resources.
  7. Adjust LVM volumes — resize logical volumes (spare, home, root, tmp, var) to match your disk capacity and workload requirements.

What Comes Next

Once the controller is running and accessible, you can proceed to configuring nodes, setting up networks, and deploying your first instances through Horizon or the OpenStack APIs.
